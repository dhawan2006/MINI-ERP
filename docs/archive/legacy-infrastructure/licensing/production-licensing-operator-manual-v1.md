# MINI POS — MASTER PRODUCTION LICENSING OPERATOR MANUAL

> **Production operator workflow is not currently implemented.**  
> Currently, there is no dedicated Admin UI or specialized CLI tool for production licensing. All operations currently rely on modifying test scripts, executing raw SQL in the Supabase Dashboard, or making manual `curl` requests to the Admin API. The safest currently supported procedures are documented below, and a formalized operator CLI tool should eventually be built.

## PART 1 — START FROM ZERO

### What is Supabase?
Supabase is the backend platform that powers Mini POS. It provides a **PostgreSQL database** (where data is stored) and **Edge Functions** (server code that handles requests).

- **Supabase project:** The container for your database, functions, and settings. Yours is `rmkosqdgltiimdhpmrsk`.
- **PostgreSQL:** A highly structured, relational database.
- **Edge Function:** A piece of secure backend code (like `api/v1/activation` or `api/v1/admin`) that executes when a client makes a request.
- **Database Table:** A grid in the database that holds specific records (e.g., `licenses`).
- **Secret:** A hidden password (like `LICENSE_KEY_HMAC_SECRET`) that is injected into Edge Functions but is never visible in plaintext.
- **Project URL:** `https://rmkosqdgltiimdhpmrsk.supabase.co` — where your app sends network requests.
- **Production vs QA:** Production holds real customer data. QA holds disposable test data. They are strictly separated.

### Architecture Overview

```text
Customer
  ↓
License Key (e.g., KCJ9B-1GB4B-GPFPC)
  ↓
Mini POS App
  ↓
Production Supabase Edge Function
  ↓
PostgreSQL Database (Validates HMAC & Device Identity)
  ↓
Signed Authorization (Ed25519 signature)
  ↓
Mini POS App (Persists locally)
  ↓
Offline Billing (Works safely without internet)
```

## PART 2 — EXPLAIN EVERY IMPORTANT TERM

- **License Key:** The 15-character string the customer enters. You MUST send this to them.
- **License ID:** A UUID (e.g., `26dbbedd-...`) that uniquely identifies the license in the database. 
- **License Record:** The row in the `licenses` table. It does NOT contain the License Key.
- **Device:** A computer running Mini POS.
- **deviceKeyId:** A unique public identifier generated by the customer's computer.
- **Device Binding:** A row in `license_bindings` tying a License ID to a `deviceKeyId`.
- **Activation:** The process of a device requesting a binding and receiving authorization.
- **Authorization:** A secure JSON document given to the device, proving it is allowed to run.
- **Ed25519:** The extremely fast, secure algorithm your server uses to sign the Authorization.
- **P-256:** The algorithm the customer's computer uses to prove its identity to your server.
- **HMAC / HMAC Secret:** The cryptographic function (and its password) used to scramble the License Key before saving it in the database.
- **validFrom / validUntil:** The exact timestamps defining when the license is active.
- **maxDevices:** The number of computers that can simultaneously use this license.
- **ACTIVE:** The state of a valid license or a working device binding.
- **DEACTIVATED:** A device binding that has been released (meaning the seat is free).
- **REVOKED:** A license that has been permanently killed by the admin.
- **EXPIRED:** A license whose `validUntil` date has passed.
- **Idempotency:** The safety feature preventing double-billing or double-binding if a network request is accidentally sent twice.
- **Challenge / Nonce / Replay:** The security mechanism preventing a hacker from recording an activation and "replaying" it on another computer.
- **Audit Event:** A permanent historical record of every lifecycle action (activation, deactivation).

## PART 3 — EXACT LICENSE KEY GENERATION

Based on `server/licensing/src/crypto/licenseKey.ts`:
1. **Randomness:** `crypto.randomBytes(15)`
2. **Byte count:** 15 bytes of pure entropy.
3. **Encoding:** Crockford's Base32 (`0123456789ABCDEFGHJKMNPQRSTVWXYZ`).
4. **Format:** `XXXXX-XXXXX-XXXXX-XXXXX-XXXXX` (25 characters).
5. **Canonicalization:** Uppercase, hyphens and invalid chars removed.
6. **HMAC-SHA-256:** The canonical key is hashed using `LICENSE_KEY_HMAC_SECRET`.
7. **Storage:** ONLY the HMAC hash is stored in PostgreSQL.
8. **Returned values:** The plaintext `licenseKey` and the database `licenseId`.

## PART 4 — EXACT PRODUCTION GENERATION PROCEDURE

> **Production operator workflow is not currently implemented.**
> There is no clean Admin CLI. The safest supported procedure currently involves using the QA generator script temporarily hooked up to Production.

**BEFORE STARTING**
1. Decide validity period.
2. Decide maxDevices.
3. Edit `server/licensing/scripts/generate-real-qa-license.ts`. **Change `validUntil.setMinutes(...)` to `setFullYear(...)` for a 1-year license.**

**GENERATE**
1. Open Terminal.
2. `cd server/licensing`
3. Edit `.env` and TEMPORARILY replace the QA credentials with:
   - `<PRODUCTION_DATABASE_URL>`
   - `<LICENSE_KEY_HMAC_SECRET>`
4. Run: `npx tsx scripts/generate-real-qa-license.ts`
5. Receive the output: `{"licenseId":"...","licenseKey":"..."}`
6. **IMMEDIATELY revert `.env` back to local QA credentials to prevent accidents.**

**AFTER GENERATION**
1. Go to Supabase Dashboard -> Table Editor -> `licenses`.
2. Verify the row exists, the status is `ACTIVE`, and `max_devices` is correct.

## PART 6 — CHECK A LICENSE

```sql
SELECT * FROM licenses WHERE id = 'the-uuid-here';
```

**Check Audit History:**
```sql
SELECT event_type, created_at, device_key_id FROM audit_events WHERE license_id = 'the-uuid-here' ORDER BY created_at DESC;
```

## PART 8 — CHECK DEVICE BINDINGS

**How to know if a seat is occupied:**
```sql
SELECT id, device_key_id, status, activated_at 
FROM license_bindings 
WHERE license_id = 'the-uuid-here' AND status = 'ACTIVE';
```
If `status` is `ACTIVE`, the seat is occupied. If `status` is `DEACTIVATED`, the seat is free.

## PART 9 — CUSTOMER ACTIVATION

**Troubleshooting Decision Tree:**
1. **Invalid key:** Did they type it right?
2. **License exists?:** Check `licenses` table.
3. **Expired?:** Is `valid_until` in the past?
4. **Revoked?:** Is `status` = 'REVOKED'?
5. **Too many devices?:** Check `license_bindings` where `status = 'ACTIVE'`.
6. **Network:** Is their computer connected to the internet?

## PART 10 — VERIFY ACTIVATION

**READ-ONLY:**
```sql
SELECT * FROM audit_events WHERE license_id = 'the-uuid' ORDER BY created_at DESC LIMIT 2;
```
You should see `LICENSE_CREATED` and `ACTIVATION_SUCCESS`.
In `license_bindings`, you should see exactly one row with `status = 'ACTIVE'`.

## PART 11 — DEACTIVATE A DEVICE

**Customer-side:** The customer clicks "Deactivate" inside Mini POS.
**Admin-side (If customer lost computer):**

**MODIFIES DATA:**
You must use the Admin API since no UI exists. Run this in Terminal:
```bash
curl -X POST https://rmkosqdgltiimdhpmrsk.supabase.co/functions/v1/admin/lifecycle/release-binding \
  -H "Authorization: Bearer <ADMIN_API_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"licenseId": "the-uuid", "deviceKeyId": "the-device-key", "reason": "Admin release"}'
```
This sets the binding to `DEACTIVATED` so a new computer can activate.

## PART 12 — TRANSFER LICENSE TO ANOTHER COMPUTER

1. **OLD DEVICE:** Deactivate via app OR Admin API `release-binding`.
2. **Seat Available:** The binding becomes `DEACTIVATED`.
3. **NEW DEVICE:** Customer installs app and types the exact same License Key.
4. **Activation:** Generates a new `deviceKeyId` and receives new authorization.

**NEVER DO THIS:** Do not copy configuration files or SQLite databases between computers. The P-256 device proof guarantees the identity is hardware-bound.

---

## PART 13 — REVOKE A LICENSE

**MODIFIES DATA:**
When a chargeback occurs, revoke the license permanently.

```bash
curl -X POST https://rmkosqdgltiimdhpmrsk.supabase.co/functions/v1/admin/lifecycle/revoke-license \
  -H "Authorization: Bearer <ADMIN_API_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"licenseId": "the-uuid", "reason": "Chargeback"}'
```

**IMPORTANT:** Because Mini POS works entirely offline, the customer's app will continue to work until their local authorization hits `validUntil`. Revocation prevents *future* renewals or new activations immediately, but does not magically break offline clients.

---

## PART 14 — RESTORE A LICENSE

**MODIFIES DATA:**
If a chargeback is resolved, restore the license:
```bash
curl -X POST https://rmkosqdgltiimdhpmrsk.supabase.co/functions/v1/admin/lifecycle/restore-license \
  -H "Authorization: Bearer <ADMIN_API_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"licenseId": "the-uuid", "reason": "Payment cleared"}'
```

**RESTORE LICENSE ≠ AUTOMATIC DEVICE REACTIVATION.** The old device bindings were killed during Revocation. The customer must manually type their key to activate again.

## PART 15 — EXPIRED LICENSE

An expired license (`valid_until` < now) will cause the offline Mini POS app to immediately deny billing finalization. 
You cannot "extend" a license in the current implementation safely without manual SQL. The best approach is to generate a brand new license and give it to the customer.

---

## PART 16 — CHECK LICENSE EXPIRY

**READ-ONLY:**
```sql
-- Expiring in next 30 days
SELECT id, valid_until FROM licenses WHERE valid_until > NOW() AND valid_until < NOW() + interval '30 days';

-- Already expired
SELECT id, valid_until FROM licenses WHERE valid_until < NOW();
```

## PART 17 — HANDLE LOST LICENSE KEY

Because `license_key_hmac` is a one-way hash, **you cannot recover a lost plaintext key from PostgreSQL.**
Workflow:
1. Find their `licenseId` in PostgreSQL using their name/email (if you kept external records).
2. Use the Admin API to `revoke-license`.
3. Generate a brand NEW license and email it to them.

## PART 19 — DELETE ONE LICENSE

**MODIFIES DATA / DANGER**
Because of foreign keys, you must delete bindings and events first.
In Supabase SQL Editor:
```sql
BEGIN;
DELETE FROM license_bindings WHERE license_id = 'uuid';
DELETE FROM activation_requests WHERE license_id = 'uuid';
DELETE FROM audit_events WHERE license_id = 'uuid';
DELETE FROM licenses WHERE id = 'uuid';
COMMIT;
```

## PART 29 — LOGS AND DEBUGGING

Troubleshooting order:
1. **Client error:** What does the UI say?
2. **Edge Function Logs:** Go to Supabase Dashboard -> Edge Functions -> Logs.
3. **Audit Events:** Check `audit_events` for the specific `license_id`.

Common Errors:
- `LICENSE_NOT_FOUND`: Typo in key.
- `LICENSE_EXPIRED`: Time has passed `valid_until`.
- `DEVICE_LIMIT_REACHED`: maxDevices exceeded. Release a binding.
